# SCOAトレーナー アプリ仕様

柏原市役所 職員採用試験（土木職B）受験者向け。**スマホで隙間時間に1問でも多く解く**ための単体HTMLアプリ。
利用シーン：電車内（片手・立ち・数分）／トイレ（1〜2分）／就寝前（暗い部屋・寝転がって）。

**成果物**：`app-shell.html`（バンク注入前のテンプレート）と `build.mjs`（ビルドスクリプト）。
最終成果物 `scoa-trainer.html` は **依存ゼロの単一HTMLファイル**。CDN・外部フォント・外部画像・fetch は一切使用禁止（`file://` で開くため）。

---

## 0. 最優先の設計原則

1. **片手・親指操作。** 選択肢ボタンは画面下半分に置く。最小タップ高 56px、間隔8px以上。
2. **1タップで再開。** 起動 → 最上部の大きなボタン1つで即出題。設定を触らせない。
3. **落ちない・消えない。** どこで閉じても次に開けば続きから。保存失敗しても壊れない。
4. **暗所配慮。** ダークテーマを既定にする。
5. 依存ゼロ・単一ファイル・オフライン完結。

## 1. データモデル

`localStorage` キー `scoa-trainer-v1`。書き込みは try/catch で包み、失敗しても動作継続。

```js
{
  v: 1,
  stats: {                  // 問題IDごとの学習状態
    "suri-001": { seen:3, ok:2, ng:1, box:2, due:1767225600000, lastAt:..., lastMs:12400, flag:false }
  },
  history: [ {id, cat, sub, ok, ms, at} ],   // 追記式。上限3000件、超えたら古い順に破棄
  days: { "2026-08-12": {n:24, ok:19} },     // 日別集計。ストリーク算出用
  resume: null | { mode, label, ids:[...], idx, log:[...], startedAt, limitMs },
  settings: { limitSec:30, timerOn:true, shuffleOpts:true, instantExp:true, theme:"dark", fontSize:"m" }
}
```

- 保存は **1問回答するたび** に実行（`resume` を含む）。途中で閉じても最大1問しか失われない。
- `JSON.parse` 失敗時は初期状態にフォールバックし、壊れたデータは `scoa-trainer-v1-broken` に退避してから上書き。
- `QuotaExceededError` を捕捉したら `history` を半分に切り詰めて再試行。

## 2. 間隔反復（Leitner）と苦手集中

- `box` は 1〜5。正解で `box+1`（上限5）、不正解で `box=1`。
- 復習間隔（`box` → 次回出題までの日数）：`[0, 1, 3, 7, 16]`（box1=同日中に再出題）。`due = lastAt + 日数*86400000`。
- **出題優先度**（降順にソートして先頭から取る）：
  1. `due` を過ぎている問題（超過が大きいほど優先）
  2. 未出題の問題
  3. `box` が小さい問題
  4. 同点はランダム
- **苦手判定**：`sub`（小分野）単位で、`seen>=3` かつ 正答率 `<60%`、または平均解答時間が制限の80%超。統計画面で赤く表示する。
- **苦手集中モード**は、苦手判定された `sub` の問題を上記優先度でキューイングする。

## 3. 画面構成

ページ遷移は行わない（単一ページ内のビュー切替）。`history.pushState` は使わない（iOSの戻るジェスチャーと競合するため）。

### 3-1. ホーム
- 上部に **[前回の続き（12/20問）]** ボタン（`resume` がある時のみ、最も大きく最上部に）
- **[さくっと10問]** — 苦手優先の10問。既定のメイン導線。トイレ・信号待ち用
- **[本番形式ミニテスト 20問]** — 尺度比率 言語3/数理4/論理4/英語5/常識4 で抽出
- **[フル模試 120問 60分]** — 言語20/数理25/論理25/英語30/常識20。全体で60分の通し時計
- **[分野別に練習]** — 5尺度 → 小分野の2階層。各項目に「n問 / 正答率x%」を表示し、苦手は赤
- **[苦手だけ集中]** — 苦手判定された小分野から出題。件数を表示
- **[間違いノート]** — 直近で不正解だった問題（`box===1` かつ `ng>0`）
- **[★ 見返す問題]** — フラグを立てた問題
- **[学習記録]** / **[設定]**
- ホーム下部に本日の実績（`24問 正答率79% / 連続7日`）を小さく表示

### 3-2. 出題（カード）
画面構成（上から）：
1. HUD：`分野・小分野` / `3 / 10` / タイマー（残り秒＋横バー）／中断ボタン（×）
2. 問題文 `q`、必要なら `s`（等幅・枠付き）、`tbl`（表）
3. 選択肢 A〜D の縦積みボタン（画面下半分に配置）
4. ★フラグのトグル

**タイマー挙動**
- `settings.timerOn` が false のときは非表示（就寝前用）。
- 残り時間は `Date.now()` の差分で計算する（`setInterval` のカウントダウン変数を信用しない）。
- `visibilitychange` で復帰したら差分から再計算する（画面ロックで時間が飛ぶため）。
- 制限超過しても**強制的に次へ進めない**。「+4.2s 超過」と赤く表示するだけ。学習が目的なので中断させない。
- **例外：フル模試モードのみ**、全体60分の残り時間を表示し、0になったら自動終了して結果へ。

**回答後**
- 正解を緑、誤選択を赤で表示。全選択肢を `disabled` に。
- `settings.instantExp` が true なら解説 `e` と `t` を即表示。false なら「解説を見る」ボタン。
- 大きな **[次へ]** ボタンを画面下部（親指位置）に出し、`focus()` する。
- 左スワイプでも次へ進める。
- 最終問題では **[結果を見る]**。

### 3-3. 結果
- 正答数／正答率の大きな表示、平均解答時間、30秒超過数
- 小分野別の内訳（正誤）
- **[間違えた問題だけもう一度]** ボタン
- **[ホームへ]**

### 3-4. 学習記録
- 通算解答数・通算正答率・**連続学習日数（ストリーク）**
- 直近14日の日別解答数（CSSだけの横棒グラフ）
- 5尺度 × 小分野の正答率一覧（**低い順にソート**、60%未満は赤、未着手はグレー）
- 平均解答時間の推移（直近50問の移動平均を数値で）
- **[データを書き出す]**：JSONを `<textarea>` に出して全選択＋クリップボードコピー、および `Blob` によるダウンロード両方を用意（iOSではダウンロードが不安定なためコピー導線が主）
- **[データを読み込む]**：JSONを貼り付けて復元。確認ダイアログを出す
- **[学習履歴をリセット]**：二段階確認

### 3-5. 設定
制限秒数（20/30/45/なし）、タイマー表示ON/OFF、選択肢シャッフル、解説の即時表示、文字サイズ（小/中/大）、テーマ（ダーク/ライト/端末に従う）

## 4. モバイル実装要件（必須）

```html
<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="theme-color" content="#0f1115">
```

- 高さは `100dvh` を使う（`100vh` はiOSのアドレスバーでずれる）。`svh/dvh` 非対応環境向けに `100vh` をフォールバックで先に書く。
- 下端の固定要素は `padding-bottom: calc(12px + env(safe-area-inset-bottom))`。
- ボタンに `touch-action: manipulation`（ダブルタップズーム防止）、`-webkit-tap-highlight-color: transparent`、`user-select: none`。
- フォントは `-apple-system, "Hiragino Sans", "Noto Sans JP", sans-serif`。本文16px以上（iOSの自動ズーム防止）。
- 縦向き・横向きどちらでも破綻しないこと。
- 選択肢が長い場合も折り返して全文表示（省略しない）。
- スワイプ判定は横移動50px以上かつ縦移動30px未満のときのみ（スクロールと誤認しない）。
- `prefers-reduced-motion` を尊重。

## 5. デザイン

既存2ファイル（`kashiwara-gijutsushoku-mensetsu-qa.html` / `scoa-jissen-drill.html`）の落ち着いた印象を引き継ぐ。派手な色・絵文字の多用・グラデーションの乱用はしない。
ダークを基調に、正誤の緑/赤だけを強い色として使う。可読性最優先。コントラスト比4.5:1以上。

## 6. 出題ロジックの注意点

- 1セッション内で同一問題を重複させない。
- 選択肢シャッフル時は正解インデックスを必ず追従させる（`a` を再計算）。
- 問題数が要求数に満たない場合は、あるだけ出題して警告を出さない（無言で縮退）。
- 苦手集中で対象0件のときは「まだ判定できません。まず50問ほど解いてください」と案内し、さくっと10問へ誘導。

## 7. ファイル契約

`app-shell.html` の `<script>` 内に次の行だけを置く。`build.mjs` がこの行を丸ごとバンク定義に置換する。

```js
/*__BANK_INJECT__*/
```

置換後は `const ALL_Q = [ ...全問題オブジェクト... ];` が定義されている状態になる。
シェル側のコードは `ALL_Q` のみを参照すること。

`build.mjs`（Node、依存なし）の動作：
1. `_build/bank/*.js` を全て読む
2. 各ファイルを `new Function` 等で評価せず、**単純な文字列処理**で `window.BANK_xxx = ` の右辺（配列リテラル）を取り出して結合する
3. `app-shell.html` の `/*__BANK_INJECT__*/` を `const ALL_Q = [...結合...];` に置換
4. リポジトリ直下に `scoa-trainer.html` を出力
5. 総問題数・尺度別内訳・ID重複数を標準出力に表示

## 8. 完了前の自己検証

1. `node build.mjs` が成功し `scoa-trainer.html` が生成される
2. `node --check` 相当で構文エラーがないこと（`<script>` 部を抜き出して確認）
3. ID重複0、総問題数が期待どおり
4. 生成ファイルに `http://` `https://` で始まる外部参照が無いこと（`grep` で確認）

報告は **5行以内**。実装した内容の要約と、仕様から外した点があればその理由のみ。
